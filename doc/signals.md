# 交易信号与连续天数

## 信号如何产生

每个交易日 `run-daily` 会：

1. 更新日线到 SQLite  
2. 用最近约 260 根 K 线计算 **中长期规则得分**（默认 ma20/60/120、60 日动量等）  
3. 写入 `signals` 表，并生成 Markdown / HTML 报告与邮件  

当日结论：

| 得分 | 信号 |
|------|------|
| ≥ 35 | 买入 |
| ≤ -35 | 卖出 |
| 其余 | 观望 |

信号对应的是 **该标的最新一根可用日线收盘后** 的计算结果，不是盘中实时价。

## 「连续 N 日买入/卖出」如何计算

报告与邮件中的 **「连续」列** 来自数据库 **历史信号**，不是人工填写：

1. 读取该标的 **全部** 已入库信号（按 `trade_date` 倒序；条数与回补/日常写入一致，通常约 120 个交易日）  
2. 从 **最近一天** 起向前数，统计与当日 **相同** 信号（买入/卖出/观望）的 **交易日天数**  
3. 遇到不同信号即停止计数（不设上限，有多少算多少）  

示例：

| 日期（新→旧） | 信号 | 连续统计 |
|---------------|------|----------|
| 周三 | 卖出 | 第 1 日 |
| 周二 | 卖出 | 第 2 日 |
| 周一 | 观望 | （打断，连续卖出仅为 2） |

报告中显示：**连续2日卖出**。

## 辅助提示（≥2 日同向）

| 连续情况 | 报告/邮件说明中的附加句 |
|----------|-------------------------|
| 连续 ≥2 日 **卖出** | 提示可考虑分批撤退；文案中建议 **≥3 日** 再加大减仓力度  
| 连续 ≥2 日 **买入** | 提示可考虑分批进入或加仓 |

仅为阅读辅助，**不构成交易指令**。

## 建议使用方式

- **单日** 买入/卖出：作观察，可不动  
- **连续 2～3 日** 同向卖出：再考虑是否撤退  
- **连续 2～3 日** 同向买入：再考虑是否加仓  

### 历史回补

`signals` 表默认只在每次 `run-daily` 时写入**最新交易日**一条，连续统计会偏短。可用：

```bash
./marketfeed signal --backfill
# 或指定最近 N 个交易日（默认 120）
./marketfeed signal --backfill --backfill-days 60
```

`bootstrap` 与 `run-daily` 完成后也会自动按最近 120 个交易日回补（需库内已有 ≥120 根日线）。

回补按**真实交易日**逐日重算，假日无 K 线则不会有对应信号行。
